# Задание 3

| Данные                       | В чём необходимость защиты                                                                                                         | Инструменты защиты                                                                                                        |
|-----------------------------|-----------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------|
| Персональные данные пациентов (PII): Ф.И.О., дата рождения, телефон, email, адрес прописки, место работы, хронические заболевания | Эти данные обладают высокой конфиденциальностью, требуют защиты от несанкционированного доступа и утечки в соответствии с требованиями российского законодательства о персональных данных (152-ФЗ). Необходимость минимизации риска потери доверия и штрафов. | Шифрование AES-256 в покое (at rest) в Secure Data Lake; TLS 1.3 при передаче (in transit); RBAC/ABAC через IAM и PEG для доступа; маскирование/обфускация в DPMS; аудит и мониторинг в CAMS и MAM; безопасное удаление по запросу (право на забвение).  |
| Медицинские карты и файлы анализа (PHI)                          | Медицинские данные находятся под особой охраной, требуют строгого контроля доступа и защиты конфиденциальности. Нарушения ведут к серьёзным репутационным и юридическим последствиям.                    | Аналогично PII: шифрование AES-256 at rest; TLS 1.3 in transit; контроль доступа через PEG и IAM; маскирование в DPMS; аудит в CAMS; мониторинг MAM; безопасное удаление по запросу.                                |
| Финансовые данные (учёт платежей, расчёты в 1С)                  | Финансовые данные важны для отчётности и налоговой безопасности, требуют конфиденциальности, аутентичности и недопустимости подделок.                                                                | Шифрование на уровне баз данных и файлов; TLS 1.3 для передачи данных между подсистемами; контроль доступа через IAM; аудит в CAMS и мониторинг MAM; интеграция с KKM через защищённые каналы.                  |
| Учёт ТМЦ (товарно-материальные ценности)                         | Данные о материальных ценностях должны быть защищены для предотвращения хищений и ошибок учёта.                                                                                                         | Шифрование at rest; TLS 1.3 для передачи; доступ по ролям в IAM; аудит и мониторинг.                                                                                 |
| Журналы приёма пациентов, записи (переходная фаза в Excel)       | Временные данные, неструктурированные, подвержены рискам потери и утечки в текущем формате. Требуется миграция в централизованную защищённую систему.                                                | Миграция в централизованное шифрованное хранилище (SDL-T); TLS 1.3 для сетевых соединений; доступ управляемый через PEG и IAM; маскирование в DPMS; аудит доступа.                                            |
| Данные интеграции с лабораторией                                | Взаимодействие с внешними системами требует защиты каналов связи и ограничения видимости данных пациентами и партнёрами.                                                                            | API защищён через Privacy Enforcement Gateway (PEG) с проверкой прав доступа; TLS 1.3; маскирование данных в DPMS; аудит CAMS; мониторинг MAM.                                                                           |
| Лог-файлы и аудиторские данные                                  | Логи доступа и изменений необходимы для расследования инцидентов и поддержки безопасности.                                                                                                            | Защищённое хранение с шифрованием; ограниченный доступ; автоматическое хранение и анализ в CAMS и MAM.                                                                  |
